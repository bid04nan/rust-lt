# Live Dashboard Integration Guide

This guide shows how to integrate the CSV-to-JSON parser with the live dashboard.

## Overview

The live dashboard displays real-time load test metrics by reading JSON data generated from CSV log files.

**Data Flow:**
```
Test Execution → CSV Logs → CsvParser → JSON File → Dashboard (fetch) → Charts/Tables
```

## Setup

### 1. Generate JSON During Test

After your test completes, parse the CSV files to JSON:

```rust
use crate::engine::reporters::live::CsvParser;

// After test execution
let parser = CsvParser::new("output", "my_scenario");
match parser.parse_csv_files() {
    Ok(live_stats) => {
        // Write JSON to file
        live_stats.to_json_file("output/live_stats.json")?;
        println!("Dashboard JSON generated at output/live_stats.json");
    }
    Err(e) => eprintln!("Failed to parse CSV: {}", e),
}
```

### 2. Serve the Dashboard

Your live server needs to serve:
- **Templates** from `src/engine/reporters/live/templates/`
- **JSON data** from the output directory (e.g., `output/live_stats.json`)

**Recommended: Implement in your existing live server**

Add these routes to your server:

```rust
// Route mappings for your live server
GET /                  → src/engine/reporters/live/templates/live.hbs
GET /live.js           → src/engine/reporters/live/templates/live.js  
GET /live_stats.json   → output/live_stats.json

// Example implementation (simplified)
use std::net::TcpListener;
use std::io::prelude::*;
use std::fs;

fn serve_dashboard(output_dir: &str) -> std::io::Result<()> {
    let listener = TcpListener::bind("127.0.0.1:8000")?;
    println!("Dashboard server running at http://127.0.0.1:8000");

    for stream in listener.incoming() {
        let mut stream = stream?;
        let mut buffer = [0; 1024];
        stream.read(&mut buffer)?;

        let request = String::from_utf8_lossy(&buffer);
        
        let (status, content_type, content) = if request.contains("GET / ") {
            // Serve template from source
            let html = fs::read_to_string("src/engine/reporters/live/templates/live.hbs")?;
            ("HTTP/1.1 200 OK", "text/html", html)
        } else if request.contains("GET /live.js") {
            // Serve JavaScript from source
            let js = fs::read_to_string("src/engine/reporters/live/templates/live.js")?;
            ("HTTP/1.1 200 OK", "application/javascript", js)
        } else if request.contains("GET /live_stats.json") {
            // Serve JSON data from output directory
            let json = fs::read_to_string(format!("{}/live_stats.json", output_dir))?;
            ("HTTP/1.1 200 OK", "application/json", json)
        } else {
            ("HTTP/1.1 404 NOT FOUND", "text/plain", "404 Not Found".to_string())
        };

        let response = format!(
            "{}\r\nContent-Type: {}\r\nContent-Length: {}\r\nAccess-Control-Allow-Origin: *\r\n\r\n{}",
            status, content_type, content.len(), content
        );

        stream.write_all(response.as_bytes())?;
        stream.flush()?;
    }

    Ok(())
}
```

### 3. Configure Dashboard

The dashboard automatically fetches JSON data every 5 seconds by default. You can adjust this:

**In live.js:**
```javascript
let refreshInterval = 5000; // Change to 2000 for 2 seconds, 10000 for 10 seconds
```

**Or use the UI:** Select refresh interval from the dropdown in the dashboard header.

### 4. Server Configuration

Your live server should be configured to:

1. **Serve static templates** from `src/engine/reporters/live/templates/`
2. **Serve dynamic JSON** from the output directory (default: `output/`)
3. **Enable CORS** if needed for cross-origin requests

No need to copy template files - they're served directly from the source directory.

## Dashboard Features

### Metrics Cards
- **Error Rate**: Percentage of failed requests
- **TPS**: Throughput (requests per second)
- **Total Requests**: Cumulative request count
- **Max VUsers**: Current active virtual users
- **P95**: 95th percentile response time
- **Duration**: Test duration (current time)

### Charts
1. **Request/Response Chart**: Requests per second over time
2. **Response Status Chart**: Distribution of request statuses
3. **Response Time Chart**: Average response time over time
4. **Errors Chart**: Error count per second
5. **Arrival Chart**: VU arrival rate
6. **Termination Chart**: VU termination rate
7. **Concurrent Users Chart**: Active VUsers over time
8. **Connections Open/Close Chart**: Connection rate
9. **TCP State Chart**: TCP connection states
10. **TCP Duration Chart**: TCP connection timing
11. **TLS Chart**: TLS handshake duration
12. **Bandwidth Chart**: Data transfer rate
13. **DNS Resolutions Chart**: DNS resolution rate
14. **DNS Duration Chart**: DNS lookup timing

### Data Tables
- **Request/Response**: Last 10 requests with details
- **Users**: Current VU state
- **Connections**: Recent connection timings
- **DNS**: Recent DNS lookups

### JSON Viewer
- Displays raw JSON data for debugging
- Auto-scroll option
- Copy to clipboard
- Download as file
- Clear viewer

## Continuous Updates During Test Execution

For real-time updates during test execution, regenerate the JSON file periodically:

```rust
use std::thread;
use std::time::Duration;
use std::sync::Arc;
use std::sync::atomic::{AtomicBool, Ordering};

fn start_json_updater(output_dir: &str, scenario: &str, running: Arc<AtomicBool>) {
    let output_dir = output_dir.to_string();
    let scenario = scenario.to_string();
    
    thread::spawn(move || {
        while running.load(Ordering::Relaxed) {
            let parser = CsvParser::new(&output_dir, &scenario);
            if let Ok(live_stats) = parser.parse_csv_files() {
                let _ = live_stats.to_json_file(&format!("{}/live_stats.json", output_dir));
            }
            thread::sleep(Duration::from_secs(2)); // Update every 2 seconds
        }
    });
}

// In your test executor:
let running = Arc::new(AtomicBool::new(true));
start_json_updater("output", "my_scenario", running.clone());

// Run test...

running.store(false, Ordering::Relaxed); // Stop updater
```

## Troubleshooting

### Dashboard shows no data
- Check that `live_stats.json` exists in the output directory
- Verify JSON file is valid (open in text editor or use `jq` tool)
- Check browser console for fetch errors (F12)
- Ensure HTTP server is serving the JSON file with correct CORS headers

### Charts not updating
- Check refresh interval setting (default 5 seconds)
- Verify JSON file is being regenerated during test
- Check browser console for JavaScript errors
- Ensure JSON structure matches expected format

### Connection errors
- Make sure HTTP server is running on correct port
- Check firewall settings
- Try accessing JSON directly: `http://localhost:8000/live_stats.json`

### Performance issues with large JSON
- Limit `recent_requests` array size using `get_recent_requests(n)`
- Increase refresh interval to reduce fetch frequency
- Consider using SSE (Server-Sent Events) for real-time streaming instead

## Migration to SSE (Optional)

For truly real-time updates, you can implement Server-Sent Events:

1. Replace `fetchLiveStats()` calls with `connectSSE()` in live.js
2. Implement an SSE endpoint that streams metrics
3. Convert metrics to the dashboard format expected by `convertRawMetricToDashboardMetric()`

This is more complex but provides instant updates without polling.
